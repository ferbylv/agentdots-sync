# agentdots-sync 使用说明

安装完成后有两种用法：

1. **交给 Agent**：在 Claude Code / Codex / Grok / OpenCode 等对话里直接说要同步、备份、恢复。
2. **自己跑命令**：对已安装技能目录里的 `scripts/sync.py` 调用。

本工具**只复制文件**，不会把 `AGENTS.md` 转成 `CLAUDE.md`，也不会改平台自己的配置格式。

把下面的 `<skill-root>` 换成技能安装后的实际目录。常见位置：

| 安装方式 | 技能根目录示例 |
| --- | --- |
| `npx skills add ferbylv/agentdots-sync`（用户级） | `~/.claude/skills/agentdots-sync`、`~/.codex/skills/agentdots-sync`、`~/.grok/skills/agentdots-sync` 等 |
| `npx skills add`（项目级） | `<项目>/.claude/skills/agentdots-sync` 或 `<项目>/.agents/skills/agentdots-sync` |
| `gh skill install ferbylv/agentdots-sync` | 对应 Agent 的 skills 目录，同上 |
| `git clone` | `<clone>/skills/agentdots-sync` |

不确定时让 Agent 用「当前已加载技能的目录」，或本地搜 `agentdots-sync/SKILL.md`。

---

## 1. 对 Agent 怎么说

装好后，用自然语言即可，例如：

- 「列出 agentdots-sync 支持的平台」
- 「先检查我本机 Claude Code 的 skills 能不能同步，不要改文件」
- 「规划把 `~/.claude` 的 skills 推到 `git@github.com:我/agent-assets.git` 的 `main`」
- 「确认计划后，把 Codex 的 AGENTS.md、rules、skills 推上去」
- 「从远程恢复我的 Claude skills，先备份再覆盖」
- 「刚才同步错了，回滚 Claude Code 最近一次备份」

Agent 应按下面约定执行：

1. 先 `--list-platforms` / `--doctor` / `--plan`（只读）。
2. 把平台、根目录、资产列表、远程、分支摊开给你看。
3. 你明确同意后，才加 `--yes` 做 apply / restore / push / rollback。
4. 「帮我同步一下」不等于允许它自己选方向或覆盖文件。

---

## 2. 自己跑命令：推荐顺序

环境：Python 3.9+；push / apply / restore 需要本机 `git` 已能访问那个远程仓库。

```bash
python3 <skill-root>/scripts/sync.py --list-platforms
python3 <skill-root>/scripts/sync.py --platform claude-code --doctor
python3 <skill-root>/scripts/sync.py --platform claude-code --plan \
  --remote git@github.com:YOUR/agent-assets.git --branch main
```

`--plan` 只打印计划，不改文件。没有 `--apply/--restore/--push/--rollback` 时，默认也是计划/检查。

核对输出里的：

- `platform` 规范名
- `root` 本地根目录
- `assets` 要动的路径
- `backup_dir` 备份目录
- `remote` / `branch`

确认后再做写操作，必须带 `--yes`。

---

## 3. 三种写操作

方向要先想清楚。`--apply` 和 `--restore` 都是 **远程 → 本地**（先备份再覆盖）；`--push` 是 **本地 → 远程**。

### 3.1 从 Git 拉到本机（新电脑 / 恢复）

```bash
python3 <skill-root>/scripts/sync.py --platform claude-code --restore --yes \
  --remote git@github.com:YOUR/agent-assets.git --branch main
```

`--apply` 效果相同，只是备份记录里的原因写成 `apply`：

```bash
python3 <skill-root>/scripts/sync.py --platform claude-code --apply --yes \
  --remote git@github.com:YOUR/agent-assets.git --branch main
```

本地已有对应文件时，会先拷到备份目录再覆盖。本地还没有这些资产时，没有可备份内容，会直接写入。

### 3.2 把本机改动推到 Git

```bash
python3 <skill-root>/scripts/sync.py --platform grok-build --push --yes \
  --remote git@github.com:YOUR/agent-assets.git --branch main \
  --message "Update Grok skills"
```

只暂存选定资产，有变更才 commit，然后普通 `git push`（**不会** `--force`）。选定路径没有变更会打印 `PUSH skipped`。

### 3.3 回滚本机最近一次备份

```bash
python3 <skill-root>/scripts/sync.py --platform claude-code --rollback --yes
```

不需要 `--remote`。只恢复备份清单里、且本次仍然选中的那些资产。

## 4. 选平台

`--platform` 默认是 **`codex`**。不同 Agent 必须显式指定，否则会去动 `~/.codex`。

| `--platform` | 别名 | 默认根目录 | 默认同步的资产 | 备份目录 |
| --- | --- | --- | --- | --- |
| `codex` | `openai-codex` | `~/.codex` | `AGENTS.md`、`rules`、`skills` | `.codex_backups` |
| `claude-code` | `claude` | `~/.claude` | `CLAUDE.md`、`rules`、`skills` | `.meta-sync-backups` |
| `opencode` | — | `~/.config/opencode` | `skills` | `.meta-sync-backups` |
| `grok-build` | `grok` | `~/.grok` | `skills` | `.meta-sync-backups` |
| `codebuddy-code` | `codebuddy` | `~/.codebuddy` | `rules`、`skills` | `.meta-sync-backups` |
| `workbuddy` | — | **必须** `--root` | `skills` | `.meta-sync-backups` |
| `custom` | — | **必须** `--root` | **必须** `--asset` | `.meta-sync-backups` |

OpenCode / Grok 的配置文件可能含环境相关内容，不要靠默认值去同步整个配置目录，用 `--asset` 精确点名。

WorkBuddy：`--root` 指向解包后的本地技能包目录；导入到 WorkBuddy 界面是另一步，本工具不管。

---

## 5. 覆盖默认路径（项目级 / 非标准目录）

重复 `--asset` 可改同步范围；`--root` 改根目录。

```bash
python3 <skill-root>/scripts/sync.py --platform custom \
  --root /path/to/agent-config \
  --asset instructions.md --asset skills --plan

python3 <skill-root>/scripts/sync.py --platform opencode \
  --root /path/to/your-project \
  --asset AGENTS.md --asset .opencode/skills --plan
```

`--backup-dir` 只能是所选 root **内部**的相对子路径。

一次只处理一个平台。不要用 Claude 的默认资产去覆盖 Codex 的文件。

---

## 6. 安全约定（使用时要知道）

- 计划、列表、`--doctor` 只读。
- 写操作必须 `--yes`。
- apply / restore / rollback 覆盖前会备份已存在的选定资产。
- 同一 root 用 `.meta-sync-lock` 串行，不要并行对同一目录做写操作。
- 选定路径不能逃出 root，不能用指向 root 外的符号链接。
- push 不会强制推送；冲突、权限失败应停止，不要让 Agent 自行解决。
- 错误输出会脱敏常见 URL 凭据和 token。

远程仓库请先自己建好、本机 Git 已能推拉。本技能**不会**帮你 `gh auth`、创建仓库或猜分支。

## 7. 完整示例：Claude Code skills 备份到 Git

假设远程是 `git@github.com:YOUR/agent-assets.git`，分支 `main`。

```bash
# 1. 看本机有没有 Claude 资产
python3 <skill-root>/scripts/sync.py --platform claude --doctor

# 2. 看将要推什么
python3 <skill-root>/scripts/sync.py --platform claude-code --push --plan \
  --remote git@github.com:YOUR/agent-assets.git --branch main

# 3. 确认后推送
python3 <skill-root>/scripts/sync.py --platform claude-code --push --yes \
  --remote git@github.com:YOUR/agent-assets.git --branch main \
  --message "Backup Claude Code skills"

# 4. 另一台机器拉下来
python3 <skill-root>/scripts/sync.py --platform claude-code --restore --yes \
  --remote git@github.com:YOUR/agent-assets.git --branch main

# 5. 拉错了就回滚
python3 <skill-root>/scripts/sync.py --platform claude-code --rollback --yes
```

别名 `claude` 与 `claude-code` 等价。

## 8. 常见问题

**命令报 `mutating actions require --yes`**  
写操作漏了 `--yes`。先 `--plan`，确认后再加。

**`platform 'workbuddy' requires explicit --root`**  
WorkBuddy / custom 没有默认家目录，必须给 `--root`；custom 还要 `--asset`。

**push 说 skipped**  
选定资产和远程一致，没有可提交变更。

**装了技能但 Agent 不用**  
确认技能在当前 Agent 的 skills 目录里，并在对话里点名「用 agentdots-sync」或说出同步/备份/恢复。纯网页聊天、不能执行本机 Python 的产品用不了。

**想把 Claude 的 CLAUDE.md 变成 Codex 的 AGENTS.md**  
本技能不做格式转换，那是另一次改写任务。
